# 表单字符长度与边界校验（仅前端）

## 范围边界

1. **包含**：**R-FORM-02**、**R-FORM-03** 中仅前端模板/样式可检部分（与 **R-UI-01** 协同的展示边界）。
2. **不包含**：联调/运行时的「满长度保存必成功」断言。

## 规则命题

1. **R-FORM-02**：可编辑文本在**前端**有**硬限制**（`maxlength` / `maxLength` / 校验器 `max` 等）及**用户可见**提示（字数统计、`show-count`、`show-word-limit`、或提交前明确报错文案）。
2. **R-FORM-03（仅静态可检部分）**：只读展示在采用**截断/省略**语义时是否与 **R-UI-01** 一致地配有 `title` / `Tooltip`（详见 **layout-long-content-overflow-tooltip**）；**不**判断业务应折行还是下拉。**不要求** Agent 断言「满长度保存一定成功」（属联调/运行时）。

## 代码观测清单

### 组件库（按项目实际核对）

| 序号 | 库 | 典型 API / 属性 |
|:----:|----|-----------------|
| 1 | **Element Plus** | `el-input` / `el-input type="textarea"`：`maxlength`、`show-word-limit`；`rules` 中 `max` |
| 2 | **Ant Design Vue** | `a-input` / `Input`、`a-textarea` / `Input.TextArea`：`maxlength`、`show-count`；`Form` 的 `rules` 中 `max` |
| 3 | **原生 DOM** | `<input maxlength="...">`、`<textarea maxlength="...">`；或在 `input` / `beforeinput` / 表单校验中限制长度 |

### 通用

- [ ] 动态表单项、弹窗子表单、`a-select mode="tags"` 等**非标单行 input** 是否同样需要上限（按产品：单 tag 长度、总字符数等）。
- [ ] 表单 `rules` 与控件 `maxlength` **不互相矛盾**（取较小者或统一为同一常量）。
- [ ] 数字类控件（`InputNumber` / `a-input-number`）：除数值范围外，若存在**字符串拼接展示**，注意异常长度展示（仅前端静态提醒，不要求压测）。


## 常见漏点

- 只校验提交按钮路径，导入弹窗、行内编辑、另一套表单无 `maxlength`
- 仅 CSS 限制宽度，无字符数上限，导致提交后由接口报错（前端仍建议补硬限制）

## 缺口计数与分列（与总控对齐；防「多文件并一条」）

本小节约束 **有序列表条数**：用户 **`@` 总控**时，总控第 3 章条数须与本专项单独执行时 **一致**。

1. **按文件下限**：凡在 **不同相对路径** 的源文件（如不同 `.vue` / `.tsx`）中各自存在 **R-FORM-02** 缺口，**每个文件至少占明细一条**；**禁止**把多个文件的缺口合并为一条（即使判定原因里用分号列举多路径）。
2. **同文件可合并的上限**：仅当缺口均在 **同一文件、同一业务表单/同一弹窗** 内，且缺失信号相同（例如多个 `a-input` 均无 `maxlength`/`show-count` 且 `rules` 均无 `max`），**允许**合并为 **一条**，但「判定原因」须点名主要字段或 `dataIndex`/表单项含义，且合并后条数 **不得少于**「有缺口的文件数」。
3. **R-FORM-03 与 R-UI-01（去重）**：同一「只读展示 + 截断、缺 `title`/Tooltip 系」锚点，在总控报告中 **只占用一章的一条明细**：**默认**归入 **第 4 章（R-UI-01）**，第 3 章 **不写**；仅当该处 **明确是表单内只读区**、不宜归 R-UI-01 叙事时，可 **只在第 3 章** 写。**禁止**同一 `[路径:行号]` 在第 3、4 章各写一条（避免条数虚增）。
4. **静态检索建议（检测根目录内）**：对 `a-input`、`a-textarea`、`Input.TextArea`、`a-input-search`、`el-input`、`textarea`、`mode="tags"`、`maxlength`、`maxLength`、`show-count`、`show-word-limit`、`rules` 中与 `max` 相关的配置做检索；对 **JSX/TSX** 中 `Input` 组件同理；**动态表单**（如 `v-for` 渲染的 `a-input`）**不得**因「配置在数据里」而跳过文件级核对。

## 输出规则（对用户报告）

1. **不输出 PASS 明细**：已满足 **R-FORM-02** / **R-FORM-03**（及与 **R-UI-01** 协同的展示项）、无需跟进的控件**不要**逐条写入报告正文，**不**占用「明细」有序列表篇幅。
2. **只输出缺口明细**（本专项下等同于 **FAIL** 或与 FAIL 等价的需跟进项）：以 **有序编号**（`1.`、`2.`、…）逐条列出；**每条单行**，顺序须为 **`{序号}. FAIL [{仓库相对路径:行号}] 判定原因：{一句话}`**（**UNKNOWN** 用时替换 **FAIL**）；「判定原因」内写无 maxlength/max、无 show-count、与 rules.max 矛盾、只读截断无 title 或 Tooltip 等，以及上限值（常量名或数字，若适用）与组件类型（Element Plus / Ant Design Vue / 原生）。**不得**省略序号。
3. **UNKNOWN / PARTIAL**：**不得**单独用 PASS 充数；须输出时**并入**上述有序列表并占用序号，或于文末**一行**汇总「待查 N 处」，仍**不**展开 PASS。
4. **可选一句总括**：仅在需要时于报告**末尾**加一句（可不编号），例如「其余已检控件未见需列入本专项的缺口」，**不得**展开 PASS 列表。

## 与总控 `verifying-ui-functional-rules` 的关系

1. 用户 **`@` 总控**或要求按 **RULE-CATALOG** 整体验证时：须遵守总控的总览表（「风险条数」与下方各章明细条数一致），以及以 `- **明细**：` 起头的有序编号列表等输出约定；**R-FORM-02**、**R-FORM-03**（及协同 **R-UI-01**）子项在明细中**只列缺口**，且**每条须带序号**；不在总控明细里堆 PASS。总控撰写第 3 章时 **须显式遵守**上文 **「缺口计数与分列」**，使条数与单独 `@` 本专项一致。
2. 用户**仅 `@` 本专项**时：正文**只写缺口明细**（与上节「输出规则」第 2 条一致），每条 **须带序号**；单行顺序与总控「统一明细行格式」一致：**FAIL → [路径:行号] → 判定原因：**。
