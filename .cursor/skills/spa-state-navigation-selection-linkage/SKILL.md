# 返回态与筛选持久化（仅前端）

## 范围边界

1. **包含**：**R-NAV-01**——路由 query、缓存 key、激活钩子中是否误清空筛选等前端可检信号。
2. **不包含**：接口返回数据是否与设计一致（除非规则仅描述前端如何展示错误）。

## 覆盖规则 ID

R-NAV-01（见 [RULE-CATALOG.md](../verifying-ui-functional-rules/RULE-CATALOG.md)）。多 Tab 排序清空见 **list-export-table-conventions**。

## R-NAV-01：返回后状态一致

**命题**：页面跳转支持返回；返回后筛选条件等与跳转前一致（**以前端状态恢复机制为准**）。

**观测**：

- `vue-router`：`query` / `meta` 持久化、`keep-alive` 含 key 策略、`pinia` / `vuex` / `sessionStorage` 恢复。
- 从详情返回列表：`onActivated` 是否误清空；浏览器后退是否命中同一缓存实例。

## 常见漏点

- 返回时 `created` 再次执行导致筛选被初始化覆盖

## 输出规则（对用户报告）


1. **不输出 PASS 明细**：已满足 **R-NAV-01**、无需跟进的项**不要**逐条写入报告正文，**不**占用「明细」有序列表篇幅。
2. **只输出缺口明细**（本专项下等同于 **FAIL** 或与 FAIL 等价的需跟进项）：以 **有序编号**（`1.`、`2.`、…）逐条列出；**每条单行**，顺序须为 **`{序号}. FAIL [{仓库相对路径:行号}] 判定原因：{一句话}`**（**UNKNOWN** 用时替换 **FAIL**）；「判定原因」内写返回后 query 未恢复、keep-alive key 不当、onActivated 误清空筛选、sessionStorage 未写入或未读出等。**不得**省略序号。
3. **UNKNOWN / PARTIAL**：**不得**单独用 PASS 充数；须输出时**并入**上述有序列表并占用序号，或于文末**一行**汇总「待查 N 处」，仍**不**展开 PASS。
4. **可选一句总括**：仅在需要时于报告**末尾**加一句（可不编号），例如「其余已检路由/返回路径未见需列入 R-NAV-01 的缺口」，**不得**展开 PASS 列表。

## 与总控 `verifying-ui-functional-rules` 的关系

1. 用户 **`@` 总控**或要求按 **RULE-CATALOG** 整体验证时：须遵守总控的总览表（「风险条数」与下方各章明细条数一致），以及以 `- **明细**：` 起头的有序编号列表等输出约定；**R-NAV-01** 子项在明细中**只列缺口**，且**每条须带序号**；不在总控明细里堆 PASS。
2. 用户**仅 `@` 本专项**时：正文**只写缺口明细**（与上节「输出规则」第 2 条一致），每条 **须带序号**；单行顺序与总控「统一明细行格式」一致：**FAIL → [路径:行号] → 判定原因：**；本文件其余章节为 **R-NAV-01** 命题与观测。
