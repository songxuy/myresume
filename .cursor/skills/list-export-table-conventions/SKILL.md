# 列表与表格（仅前端）


## 范围边界

1. **包含**：**R-EXPORT-01**——导出请求发起后至前端得到可下载结果或错误终态前，用户侧可感知的「进行中 / 结束 / 失败」信号（见下节）。
2. **不包含**：服务端导出任务队列、接口真实耗时结论。

## 覆盖规则 ID

**R-EXPORT-01**（见 [RULE-CATALOG.md](../verifying-ui-functional-rules/RULE-CATALOG.md)）。

## 命题与观测（R-EXPORT-01）

- **同步导出**（直接 `blob` / `downloadFile` / `utils.download` 等）：导出入口须有与本次请求绑定的 **`loading`**、全屏 **`loading`**、或**禁用**直至前端收到成功下载或错误分支处理完毕。
- **异步导出**（仅提交任务、轮询、WebSocket、结果页等）：须有**前端状态机或 UI** 能区分进行中与结束/失败（提示、进度、结果区、按钮态等）；不要求测真实排队时间。

## 检索关键词

`export`、`download`、`downloadFile`、`loading`、`exportLoading`、`disabled`、`轮询`、`poll`、`taskId`、`导出`

## 常见漏点

- 导出按钮无 `:loading` / `loading`，`async export` 内也未在 `await` 前置位与 `finally` 复位。
- 仅列表查询共用 `loading`，导出与查询竞态时用户无法区分「正在导出」。

## 输出规则（对用户报告）

1. **不输出 PASS 明细**。
2. **只输出缺口明细**（本专项下 **R-EXPORT-01** 的 FAIL 或等价需跟进项）：以有序编号（`1.`、`2.`、…）逐条列出；**每条单行**，顺序须为 **`{序号}. FAIL [{仓库相对路径:行号}] 判定原因：{一句话}`**，且「判定原因」句内或句末**须**出现 **R-EXPORT-01**；**UNKNOWN** 用时将 **FAIL** 换为 **UNKNOWN**；「判定原因」内写导出无 loading、无进行中提示、异步导出无状态机等缺失信号。**不得**省略序号。
3. **UNKNOWN**：须输出时并入上述有序列表并占用序号，或文末一行汇总「待查 N 处」，仍不展开 PASS。
4. **可选一句总括**：仅在需要时于报告末尾加一句（可不编号），**不得**展开 PASS 列表。

## 与总控 `verifying-ui-functional-rules` 的关系

1. 用户 **`@` 总控**或要求按 **RULE-CATALOG** 整体验证时：遵守总控总览表（「风险条数」与下方各章明细条数一致）及 `- **明细**：` 起头的有序编号等约定；**R-EXPORT-01** 子项在明细中只列缺口且每条须带序号。
2. 用户**仅 `@` 本专项**时：正文只写 **R-EXPORT-01** 缺口明细（与上节第 2 条一致）；单行顺序与总控「统一明细行格式」一致，且句末或句内须含 **R-EXPORT-01**。
