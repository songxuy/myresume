## 触发条件

当用户提到以下关键词时，必须触发本约束：
- "设计"、"需求"、"开始开发"、"启动项目"
- "新功能"、"功能开发"、"实现"
- "项目启动"、"从零开始"

## 约束规则

### 必做事项：需求资料确认

在开始任何设计/开发工作之前，**必须**向用户确认是否具备以下基础资料：

| 资料类型 | 说明 |
|----------|------|
| 需求设计文档 | PRD、MRD、用户故事等 |
| 原型设计 | 线框图、交互原型 |
| UI 设计 | 设计稿、切图资源 |
| 其他相关资料 | API 文档、技术方案等 |

### 确认话术

```
在开始之前，请确认您是否已具备以下资料：
- 需求设计文档（PRD/用户故事）
- 原型设计（如果涉及交互）
- UI 设计稿（如果涉及界面）

如果有，请提供资料所在目录或上传文件。
如果暂未准备，我可以先帮您设计基础模板，待您补充后再继续。
```

## 输出文档要求

### 文档命名规范

```
需求设计说明书_v{版本号}.md
```

例如：`需求设计说明书_v1.0.md`、`需求设计说明书_v2.1.md`

**版本号必须与用户确认**，在开始设计前询问：
```
"请确认本次需求的版本号（如 v1.0、v2.0）："
```

### 文档存放位置

```
/workspace/docs/requirements/
```

### 版本追溯要求

**硬性要求**：
1. **每个版本的设计必须参考历史版本文档**
2. **新版本设计时，必须包含以下内容：**
   - 基于前版本的变更说明
   - 功能继承与扩展列表
   - 确保不脱离原有设计范围
3. **维护版本变更记录**

## 需求变更/迭代约束

### 触发条件

当用户提出以下类型的请求时，触发兼容性确认：
- 对已有功能的修改/调整
- 功能扩展/增强
- 需求变更
- 版本迭代

### 兼容性确认流程

```
[检测到需求变更请求]
        │
        ▼
[识别受影响的已有功能]
        │
        ▼
[向用户确认兼容性]
        │
        ▼
┌─────────────────────────────────────┐
│ "以下功能将受到影响："               │
│ - [功能A]                           │
│ - [功能B]                           │
│                                     │
│ "请确认变更是否兼容原有设计："       │
│ A. 兼容 - 不影响现有功能使用         │
│ B. 不兼容 - 需要同步调整相关功能     │
│ C. 取消 - 暂不变更                   │
└─────────────────────────────────────┘
        │
        ▼
[等待用户选择]
```

### 兼容性评估维度

| 评估维度 | 说明 |
|----------|------|
| **功能兼容性** | 变更是否影响现有功能的使用方式 |
| **数据兼容性** | 变更是否影响现有数据的存储和读取 |
| **接口兼容性** | 变更是否影响与外部系统的接口调用 |
| **UI 兼容性** | 变更是否影响用户已形成的操作习惯 |

### 变更影响分析

**必须记录以下内容**：
1. 受影响的已有功能列表
2. 影响程度评估（高/中/低）
3. 建议的同步调整方案
4. 用户确认的兼容性类型（A/B/C）

### 不兼容时的处理

如果用户选择 **B（不兼容）**：
1. 列出所有需要同步调整的功能
2. 评估变更范围和风险
3. 制定同步调整方案
4. 获得用户确认后再继续
5. 在新版本文档中详细记录所有变更

## 硬性要求

1. **不得在未确认资料的情况下直接开始设计/开发**
2. **如果用户选择A，必须先完成基础模板设计**
3. **模板设计应包含：需求文档模板、原型框架、UI规范初稿**
4. **需求设计完成后，必须输出 "需求设计说明书_v{版本号}.md"**
5. **需求设计完成后，禁止直接进入开发阶段，必须等待用户指令**
6. **每个新版本必须参考历史版本文档，确保功能完整性**
7. **需求变更时，必须识别受影响的已有功能，并与用户确认兼容性**
8. **设计完成后，必须询问用户是否需要提交**
9. **提交时必须确认提交用户信息**

## 设计完成后提交确认

### 提交确认流程

```
[设计文档完成]
        │
        ▼
[询问用户]
        │
        ▼
┌─────────────────────────────────────┐
│ "需求设计说明书已生成完毕。"         │
│                                     │
│ "是否需要提交？"                     │
│ A. 提交                             │
│ B. 暂不提交                         │
└─────────────────────────────────────┘
        │
        ▼
[用户选择]
  - A → [确认提交用户信息] → [执行提交]
  - B → [结束，等待用户指令]
```

### 提交用户信息确认

**如果用户选择提交，必须确认以下信息**：

```
┌─────────────────────────────────────┐
│ "请确认提交信息："                   │
│                                     │
│ 提交用户：[用户名/姓名]              │
│ 提交邮箱：[邮箱地址]                 │
│ 提交分支：[分支名]                   │
│                                     │
│ 请确认信息是否正确？"               │
│ A. 确认提交                         │
│ B. 修改信息                         │
└─────────────────────────────────────┘
```

**如果用户选择修改**：请用户提供正确的用户信息后重新确认。

### 提交执行

确认用户信息后，执行以下操作：
1. 初始化 Git 仓库（如尚未初始化）
2. 配置用户信息（仅本次提交）
3. 添加设计文档到暂存区
4. 提交并添加提交信息
5. 记录提交结果反馈给用户

